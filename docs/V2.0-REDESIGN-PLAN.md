## 1. 技术选型

### 1.1 主选：react-three-fiber + drei + three-pathfinding

| 维度 | 值 | 来源 |
|---|---|---|
| **核心库** | `@react-three/fiber@^8.17.10`（r3f v9 需 React 19，项目用 React 18）| https://github.com/pmndrs/react-three-fiber |
| **drei** | `@react-three/drei@^10.7.8`（2026-08-05 release）| https://github.com/pmndrs/drei/releases |
| **three.js** | `r170+` | threejs.org |
| **three-pathfinding** | latest（Don McCurdy 维护，活跃）| https://github.com/donmccurdy/three-pathfinding |
| **Bundle 增量** | ~200 KB gzip（r3f ~12KB + drei 按需 ~25KB + three core ~150KB）| 业内估算 |
| **学习曲线** | 中。需懂 Three.js 基础（geometry/material/camera/scene）+ JSX = `<mesh>` | r3f 官方文档 |
| **活跃度** | r3f 28k stars + drei 31.8k stars + pmndrs 团队 5 人核心，2026-08-05 才发版 | GitHub |
| **Next.js 14 集成** | `'use client'` + `dynamic(..., {ssr:false})` + `next.config.mjs` 加 `transpilePackages: ['three']` | r3f 官方 |

### 1.2 为什么不用其他库

| 库 | 排除原因 |
|---|---|
| **PixiJS v8** | 2.5D 是仿的（affine 投影，非真 3D）；sprite sheet 需要美术产出 |
| **Spine + Pixi** | Spine Editor 付费（$70/月），个人项目不必要 |
| **Phaser 4 + react-phaser-fiber** | react-phaser-fiber 已 404；Phaser ~900KB 是 r3f 4 倍，杀鸡用牛刀 |
| **Lottie-react** | **2026-06-20 仓库已 archive**，直接排除 |
| **react-konva** | 2D Canvas，无 3D 概念；仿 2.5D 需要大量手写 transform 矩阵，违反"用现成包" |
| **Live2D Cubism** | 闭源 SDK + 需 Cubism Editor，个人项目 over-engineer |
| **自写 SVG + framer-motion variants** | bundle 0 但视觉保真度低，用户明确说"简陋" |

### 1.3 关键技术决策

**D1：MeshToonMaterial 而非 MeshStandardMaterial**
- MeshToonMaterial 是 Three.js 内置卡通材质，无需写 GLSL shader
- 配合 `gradientMap`（3-5 像素灰度图）做 cel-shading 阶梯光影
- 一行 JSX：`<meshToonMaterial color="#5b8def" gradientMap={gradientMap} />`

**D2：OrthographicCamera + 2.5D 等距视角**
- 法官席顶部居中，正反方左右，调查员中央顶，书记员底部居中
- 固定等距视角（不旋转），类似《逆转裁判》sprite 风格
- 三行 JSX：
  ```tsx
  <OrthographicCamera makeDefault position={[8, 8, 8]} zoom={50} />
  <directionalLight position={[5, 10, 5]} intensity={1.2} />
  <AccumulativeShadows temporal frames={60} alphaTest={0.85}>
  ```

**D3：状态机保留 + framer-motion 不直接驱动 r3f**
- 现有 `AvatarAnimations.tsx + variants.ts` 6 状态（idle/speaking/listening/searching/judging/confronting）保留为**驱动层**
- framer-motion 用于 DOM 元素（按钮/tab/卡片）
- r3f Canvas 内用 `useFrame` + `useAnimations`，**不用 framer-motion**（设计目标不同）
- 状态机映射：`state` → `actions['walk'].fadeIn(0.2).play()`

**D4：无细节面部 = 反而简化**
- 用户明确"眼睛都不要有"
- r3f 角色 = 几何体（capsule body + sphere head），原本无 mesh 的"面部"概念
- 直接不画眼睛/嘴/眉毛，节省贴图 + 简化 mesh 树

## 5. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| r3f bundle +200KB 影响庭审页 LCP | 首屏加载变慢 | 懒加载 Canvas + `ssr:false`；主页/登录页不引入 r3f |
| three-pathfinding 文档少 | 跑位实现难 | 用 npm 上的 navmesh 工具生成 demo navmesh；先做静态 5 节点寻路验证 |
| Next.js 14 hydration mismatch | 服务端渲染异常 | r3f Canvas 必须 `dynamic + ssr:false`（官方推荐）|
| React 18 vs 19 边界 | r3f v9 需 React 19 | 用 r3f v8 配 React 18 |
| ToonMaterial 在低端 GPU 卡顿 | 用户设备差异 | 庭审页用户群体个人项目，GPU 普遍良好；如有问题降级到 MeshLambertMaterial |
| 用户中途再次反馈"还不够" | 反复重做 PR | 每个阶段交付后用户浏览器实测，不满意及时调整下一阶段方向 |

## 6. 不做什么（明确边界）

- ❌ **不引入 .glb / .fbx 3D 模型资产**（纯几何体 + MeshToonMaterial）
- ❌ **不做面部表情 / 眼睛 / 嘴**（用户明确"无细节"）
- ❌ **不做镜头推拉 / 全景**（保持 2.5D 等距视角固定）
- ❌ **不重写 MessageHistory / EvidenceBoard / sidebar**（只改庭审场景）
- ❌ **不删除 AvatarAnimations.tsx / variants.ts 6 状态**（保留为驱动层）
- ❌ **不替换 framer-motion 11**（保留用于 DOM 元素）
- ❌ **不引入 Spine / Live2D / Lottie**（已 archive 或 over-engineer）
- ❌ **不引入 GSAP**（framer-motion + r3f useFrame 已够）
