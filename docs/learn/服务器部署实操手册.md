# 服务器部署实操手册（手动版）

> 记录 2026-09-20 把 DecisionCourt 部署到腾讯云 CVM 的完整过程。
> 每条命令都给「**原始写法 + 为什么**」，可以照着从头做一遍。
>
> 本文是**学习材料**（放在 `docs/learn/`），不是项目主文档。主文档见 `docs/` 下其他文件。

---

## 0. 先搞清楚：谁做了什么

上一轮部署里，绝大部分命令是我通过一个 Python SSH 脚本远程执行的，你只在控制台点了几个按钮。对照表：

| 环节 | 我实际用的方式 | 你手动练习时的等价操作 |
|---|---|---|
| 本机 SSH 连接 | `paramiko`（Python 库）读写密码 | Windows 自带 `ssh` 命令，交互输密码 |
| 服务器初始化 | 上传 `bootstrap-server.sh` 远程执行 | 手动 `ssh` 进去，逐条敲（见 §5） |
| 传代码 | SFTP 上传 tar.gz | `git clone` 或 `scp`（见 §6） |
| 改 .env | `step3-env.sh` 用 sed 批量改 | `nano .env` 手动改（见 §7） |
| 构建启动 | `nohup docker compose up -d --build &` | 同一条命令，直接前台跑 |
| 验证 | 远程 `curl` | 本地浏览器 + `curl.exe` |

**为什么我要用 paramiko？** Windows 没有 `sshpass`，没法在非交互的脚本里输密码；而且我要连续执行几十条命令、看长日志、传文件。**你自己练习时完全不需要它**——Windows 自带的 `ssh` 是交互式的，输密码、敲命令都很直观，反而更适合学习。

## 2. 第一步：连上服务器

### 2.1 用 Windows 自带的 ssh（推荐入门）

打开 **PowerShell** 或 **Windows Terminal**，敲：

```powershell
ssh ubuntu@49.235.176.27
```

第一次连接会看到：

```
The authenticity of host '49.235.176.27' can't be established.
ED25519 key fingerprint is SHA256:xxxxx...
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

输入 `yes` 回车。这是一次性的主机指纹确认——SSH 靠它防止有人中间冒充你的服务器。确认过之后指纹存进 `~/.ssh/known_hosts`，以后不再问。

然后提示 `ubuntu@49.235.176.27's password:`，**粘贴密码时屏幕上不会有任何显示**（不是卡住了，这是正常的安全设计），直接回车。

看到提示符变成 `ubuntu@VM-xx-xx-ubuntu:~$` 就成功了。先跑三条命令熟悉环境：

```bash
whoami              # 我是谁 → ubuntu
hostname            # 主机名
cat /etc/os-release | head -3   # 系统版本
nproc               # CPU 核数 → 2
free -m             # 内存 → 约 1967MB，swap 行初始是 0
df -h /             # 磁盘 → 50G
```

**退出连接**：敲 `exit`，或按 `Ctrl+D`。

### 2.2 密码登录失败怎么排查（我踩过的坑）

如果你遇到 `Permission denied (publickey,password)`，按顺序检查：

**① 用户名对不对**（90% 的原因）

```powershell
ssh ubuntu@49.235.176.27    # 腾讯云 Ubuntu 镜像用这个
```

不要用 `root`（密码登录被禁）、不要用 `lighthouse`（那是轻量服务器的用户）。

**② 密码有没有串字符**

复制密码时注意：控制台里显示的密码如果有前导短横线，那可能**不是密码的一部分**（是列表的符号）。密码里的 `!` `@` `#` 在某些终端有特殊含义——用**双引号包起来**最保险：

```powershell
ssh ubuntu@49.235.176.27 "-NrfppjgGY_C8FD"
```

（这只是举例，实际这样传密码并不规范，只是说明引号的作用。）

**③ 连续失败会被临时限流**

腾讯云 CVM 的 sshd 有防爆破机制，同一 IP 连续失败几次后会**临时拒绝所有认证请求**（即使密码是对的）。我中间就被锁了两次，等 3-5 分钟自动恢复。

所以：**不要反复重试**，确认用户名和密码后一次性登录。

**④ 换密码后必须重启实例**

在控制台「重置密码」后，新密码**关机重启才生效**：

```text
控制台 → 实例 → 更多 → 实例状态 → 关机
       → 更多 → 密码/密钥 → 重置密码 → 填新密码
       → 开机（约 2 分钟）
```

**⑤ 终极手段：重置密码 + 换成密钥登录**

如果密码怎么都不行，直接跳到 §3 用密钥（更可靠，也是生产标准）。

### 2.3 进阶：VS Code Remote-SSH（强烈推荐）

装了密钥之后，用 VS Code 连服务器写代码/改配置，比在终端里敲 `nano` 舒服得多：

1. VS Code 装扩展 **Remote - SSH**（微软官方）
2. `Ctrl+Shift+P` → `Remote-SSH: Connect to Host` → `ubuntu@49.235.176.27`
3. 连上后 `文件 → 打开文件夹` → `/opt/DecisionCourt`

现在你的 VS Code 里能直接看到服务器文件、内置终端，改 `.env` 和改本地文件一样。**日常运维 80% 的时间可以用这个搞定。**

## 3. 第二步：免密登录（SSH 密钥）

### 3.1 为什么要做这一步

| 维度 | 密码登录 | 密钥登录 |
|---|---|---|
| 安全性 | 可被暴力破解（你的服务器 22 端口每分钟都在被人扫） | 数学上不可暴力破解 |
| 体验 | 每次输密码 | 直接进 |
| 自动化 | **无法用于 CI/CD** | 是 GitHub Actions 部署的唯一方式 |
| 失败限流 | 有（见 §2.2③） | 几乎不会触发 |

第 4 阶段的 CI/CD 强制要求密钥，所以这一步不是可选优化，是必经之路。

### 3.2 本机生成密钥（如果还没有）

先检查：

```powershell
ls ~/.ssh
```

有 `id_ed25519` 和 `id_ed25519.pub` 就跳过。没有的话生成：

```powershell
ssh-keygen -t ed25519 -C "你的邮箱@example.com"
```

一路回车（密码短语留空 = 免密使用，练习场景够用）。

生成的是**一对**：
- `id_ed25519` —— **私钥**，绝对不外泄，留在你电脑里
- `id_ed25519.pub` —— **公钥**，要装到服务器上

### 3.3 把公钥装到服务器

`ssh-copy-id` 在 Windows 上没有，**手动做**（三行，比想象中的简单）：

**第 1 步**：本地读出公钥内容

```powershell
Get-Content ~/.ssh/id_ed25519.pub
```

会输出一行，形如：

```
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIIL95MkqjwHszrrZghUUGut+X4VW/tIvJvfGBa+8hXrJ 2421389161@qq.com
```

**整行复制**（从 `ssh-ed25519` 到最后）。

**第 2 步**：登录服务器（用密码），在服务器上执行

```bash
mkdir -p ~/.ssh && chmod 700 ~/.ssh
echo '刚才复制的那一整行公钥' >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

> 权限说明：`~/.ssh` 必须是 700、`authorized_keys` 必须是 600，否则 sshd **会直接忽略**这个文件（这是 SSH 的安全设计，权限太松就等于谁都能改）。这一步忘了做是新手最常见的失败原因。

**第 3 步**：本地重新连接，验证

```powershell
ssh ubuntu@49.235.176.27
```

如果**不再提示输密码**直接进入，就成功了。

> 我上一轮做的事等价于：本地把公钥写进脚本，远程 `cat >> ~/.ssh/authorized_keys`。装完之后我后续所有操作都走密钥，不用再碰密码。

### 3.4 验证当前用的是哪种方式

```powershell
ssh -v ubuntu@49.235.176.27 exit 2>&1 | Select-String "Authenticated to"
```

输出 `Authenticated to ... using "publickey"` 就是密钥在生效。

### 3.5 （可选，进阶）禁用密码登录

确认密钥登录完全可用之后，可以关掉密码登录以彻底消除爆破风险：

```bash
sudo nano /etc/ssh/sshd_config.d/99-hardening.conf
```

写入：

```text
PasswordAuthentication no
PermitRootLogin no
```

然后：

```bash
sudo systemctl restart ssh
```

> **警告：做这一步之前，务必在另一个终端确认密钥登录是好的**，否则可能把自己锁在服务器外面。学习期可以先不做，等熟练了再上。

## 4. 第三步：服务器初始化

这一步我用了 `bootstrap-server.sh` 一次跑完。手动做就是把下面 5 小节逐条敲一遍。

### 4.1 更新系统 + 装基础软件

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl gnupg git jq unzip
```

### 4.2 加 swap（**2C2G 必须做，不是可选**）

**为什么必须做**：这个项目构建 Next.js 前端时内存峰值会超过 2GB，物理内存不够就会被内核 OOM Killer 杀掉构建进程。**原作者当年就是因为这个，被迫把架构改成「本地构建镜像 → 推送到镜像仓库 → 服务器只拉不建」**（源码注释里写着 `v0.9.1: ECS 2C2G build OOM`）。我们加 3GB swap 就把这个问题从根上解决了。

```bash
sudo fallocate -l 3G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# 开机自动挂载
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# 降低交换倾向（10 = 优先用物理内存，内存不够才用 swap）
sudo sysctl -w vm.swappiness=10
echo 'vm.swappiness=10' | sudo tee -a /etc/sysctl.conf

# 验证：看到 Swap 那行不是 0
free -m
```

> 小知识：`vm.swappiness=10` 意思是「尽可能用物理内存，实在不够才换出」。服务器场景通常设 10（默认 60 太激进，会让活跃进程被换出、变慢）。

### 4.3 装 Docker（走腾讯云内网源，快很多）

```bash
# 1) 装 GPG 密钥
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://mirrors.cloud.tencent.com/docker-ce/linux/ubuntu/gpg \
  | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

# 2) 加软件源（自动识别 Ubuntu 代号 jammy/noble）
CODENAME=$(. /etc/os-release && echo "$VERSION_CODENAME")
ARCH=$(dpkg --print-architecture)
echo "deb [arch=$ARCH signed-by=/etc/apt/keyrings/docker.gpg] https://mirrors.cloud.tencent.com/docker-ce/linux/ubuntu $CODENAME stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list

# 3) 安装
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# 4) 验证
docker --version           # Docker version 29.8.1
docker compose version     # Docker Compose version v5.5.1
```

**为什么用 `docker-ce` 而不用 `docker.io`？** 官方仓库版本新、compose v2 插件完整；Ubuntu 自带的 `docker.io` 版本老、没有 compose 插件。

### 4.4 配镜像加速（大陆服务器必做）

**为什么**：Docker Hub (`registry-1.docker.io`) 在国内被 DNS 污染，不配加速连 `postgres:15-alpine` 都拉不下来。

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json > /dev/null <<'EOF'
{
  "registry-mirrors": [
    "https://mirror.ccs.tencentyun.com",
    "https://docker.m.daocloud.io",
    "https://docker.1panel.live"
  ],
  "log-driver": "json-file",
  "log-opts": { "max-size": "10m", "max-file": "3" },
  "live-restore": true
}
EOF

sudo systemctl restart docker
sleep 3

# 验证：末尾能看到 registry-mirrors 那三个地址
docker info | grep -A3 "Registry Mirrors"
```

逐项解释：

| 配置 | 作用 |
|---|---|
| `registry-mirrors` | 第一个是腾讯云**内网**镜像站（免费、最快），后两个是公网备用 |
| `log-driver` + `max-size` | 容器日志最多 10MB × 3 份，**防止日志把磁盘写满** |
| `live-restore` | Docker 重启时容器不中断（升级 docker 时有用） |

> 本地 Windows 上我也做过同样的事（写 `C:\Users\<你>\.docker\daemon.json`），因为 Docker Desktop 用的也是这个文件。区别是本地第一个镜像用 `docker.m.daocloud.io`（没有腾讯云内网）。

### 4.5 建项目目录 + 加 docker 组

```bash
sudo usermod -aG docker ubuntu     # 让 ubuntu 用户能用 docker（不用每次 sudo）
sudo mkdir -p /opt/DecisionCourt
sudo chown -R ubuntu:ubuntu /opt/DecisionCourt

# 验证（需要重新登录才生效）
exit
```

重新 `ssh ubuntu@...` 进来后：

```bash
docker ps    # 不加 sudo 也能跑 = docker 组生效
id -nG ubuntu | tr ' ' '\n' | grep docker
```

## 5. 第四步：把代码放到服务器

两种方式，**推荐方式 A**。

### 方式 A：git clone（真实工作流，推荐）

前提：代码已经推到 GitHub（上一轮你在自己终端里推成功了，远程是 `git@github.com:to-resolve/DecisionCourt.git`）。

```bash
cd /opt/DecisionCourt
git clone git@github.com:to-resolve/DecisionCourt.git .
```

> 服务器上首次 git clone SSH 地址需要部署密钥。简单做法是用 HTTPS：
> ```bash
> git clone https://github.com/to-resolve/DecisionCourt.git .
> ```
> 私有仓库会要求输入 GitHub 用户名 + **Personal Access Token**（不是登录密码！在 GitHub → Settings → Developer settings → Personal access tokens 里生成，勾 `repo` 权限）。

**注意**：clone 下来的**没有 `.env`**（它在 gitignore 里），要手动创建，见 §6。

### 方式 B：scp 传压缩包（我上一轮用的）

为什么当时的代码用这个方式：GitHub push 卡在凭据窗口（非交互环境拿不到授权），但我不想让部署停在等授权上，所以先把本地打包传上去。

本地 PowerShell：

```powershell
cd E:\Code\DecisionCourt-new

# 1) 打包（排除不需要的目录）
tar -czf "$env:TEMP\dc_repo.tar.gz" `
  --exclude=./.git --exclude=./.workbuddy --exclude=./secrets `
  --exclude=./logs --exclude=node_modules --exclude=.next `
  --exclude=test-output .

# 2) 确认打包内容（关键：确认 .env 打包进去了、secrets 没进去）
tar -tzf "$env:TEMP\dc_repo.tar.gz" | Select-String "^\./\.env$"
tar -tzf "$env:TEMP\dc_repo.tar.gz" | Select-String "^\./secrets/"   # 应该没有输出

# 3) 上传
scp "$env:TEMP\dc_repo.tar.gz" ubuntu@49.235.176.27:/tmp/dc_repo.tar.gz
```

服务器上解压：

```bash
sudo mkdir -p /opt/DecisionCourt
sudo chown -R ubuntu:ubuntu /opt/DecisionCourt
tar -xzf /tmp/dc_repo.tar.gz -C /opt/DecisionCourt

# compose 需要写日志目录
mkdir -p /opt/DecisionCourt/logs/backend /opt/DecisionCourt/logs/caddy

# 确认关键文件都在
ls /opt/DecisionCourt/{docker-compose.yml,deploy/caddy/Caddyfile,.env}
```

> 为什么 `.env` 要打包进去但 `secrets/` 不要？`.env` 是应用的配置（里面有你本地开发用的 key，服务器上我会改掉敏感项）；`secrets/` 里是服务器的登录凭据，**绝不能上服务器**。

## 6. 第五步：配置 .env

`.env` 是整套部署的核心，服务器上的配置和本地开发有 5 处关键差异。

```bash
cd /opt/DecisionCourt
cp .env .env.bak        # 改之前先备份，出问题能回滚
nano .env
```

（`nano` 保存是 `Ctrl+O` 回车，退出是 `Ctrl+X`。）

| 项 | 本地开发值 | 服务器值 | 为什么 |
|---|---|---|---|
| `POSTGRES_PASSWORD` | `devpassword` | **服务器本地随机生成** | 生产不能用开发密码 |
| `DATABASE_URL` | `...@localhost:5432/...` | `...@postgres:5432/...` | 容器里的 `localhost` 指容器自己，连数据库要用**服务名** |
| `JWT_SECRET` | 本地那个 | **服务器本地随机生成** | 同上，且决定所有用户登录态 |
| `ALLOWED_ORIGINS` | `http://localhost,...` | `http://49.235.176.27:8080,...` | 后端 CORS 白名单，不匹配会直接拒请求 |
| `NEXT_PUBLIC_API_URL` | `http://localhost` | `http://49.235.176.27:8080` | **构建期变量**，前端代码里写死的地址 |
| `NEXT_PUBLIC_WS_URL` | `ws://localhost` | `ws://49.235.176.27:8080` | WebSocket 地址 |
| `DOMAIN` | `:80` | `:80` | Caddy 监听配置（`:80` = 监听 80 端口，不是域名） |
| `CADDY_HTTP_PORT` | （无） | `8080` | **新增**：把容器 80 映射到主机 8080，绕开备案扫描 |

生成随机密钥：

```bash
# 数据库密码：32 位
openssl rand -base64 32 | tr -d '/+=' | head -c 32

# JWT 密钥：更长的随机串
openssl rand -base64 48 | tr -d '\n'
```

把输出分别填进 `POSTGRES_PASSWORD` 和 `JWT_SECRET`，并**同步更新 `DATABASE_URL` 里的密码部分**（这三处必须一致，否则后端连不上库）。

最后收权限：

```bash
chmod 600 /opt/DecisionCourt/.env
```

> **重要认知**：`NEXT_PUBLIC_API_URL` 和 `SEARCH_PROVIDER` 的类型完全不同！
> - `NEXT_PUBLIC_*` 是**构建期变量**——`next build` 时就被编译进 JS 产物，改了必须 `--build` 重新构建
> - `SEARCH_PROVIDER` / `JWT_SECRET` 等是**运行时变量**——容器启动时读取，改了只要 `docker compose up -d` 重启容器
>
> 这就是为什么改 IP 相关的配置必须重新构建前端。

## 7. 第六步：构建启动

```bash
cd /opt/DecisionCourt

# 直接跑（前台，会看到实时输出）
docker compose up -d --build
```

**如果 SSH 会话可能中断**（比如网络抖动），用后台方式跑，输出写日志：

```bash
nohup docker compose up -d --build > /tmp/dc_build.log 2>&1 &
```

然后另开一个连接看进度：

```bash
tail -f /tmp/dc_build.log
```

（`tail -f` 是实时跟踪，`Ctrl+C` 退出跟踪但**不会**停掉后台构建。）

**构建要多久**：2C2G 加 swap 大约 **8-15 分钟**。会依次看到：

1. 拉基础镜像（golang / node / postgres / redis / caddy）—— 走镜像加速，1-2 分钟
2. backend：`go mod download`（走 goproxy.cn）→ `go build`
3. frontend：`pnpm install`（走 npmmirror）→ `next build`（**最吃内存，最慢的一步**）
4. 组装镜像 → 启动 5 个容器

**构建期间看内存**（另开一个终端）：

```bash
free -m          # 看 swap 有没有被用起来
```

## 10. 踩坑记录（上一轮真实遇到的）

| # | 现象 | 真因 | 解法 |
|---|---|---|---|
| 1 | 密码登录一直失败，以为密码错 | **腾讯云 Ubuntu 镜像默认用户是 `ubuntu` 不是 root** | 用 `ssh ubuntu@IP` |
| 2 | 换新密码还是失败 | 我的脚本 `ECS_USER` 默认值写死成 `root`，把配置里的 `ubuntu` 覆盖了 | 默认值留空再兜底 |
| 3 | 连续失败后连正确密码也被拒 | sshd 防爆破限流（CVM 特性） | 停止重试，等 3-5 分钟 |
| 4 | 后端容器 panic 退出 | `ALLOWED_ORIGINS` 少写了 `http://` 前缀 | 补全协议头 |
| 5 | Caddy 容器起不来 | Caddyfile 用了非标准的 `access_log` 指令 | 换成标准 `log` 指令 |
| 6 | Docker Hub 拉镜像超时 | DNS 污染 | daemon.json 配镜像加速 |
| 7 | 前端构建 OOM 风险 | 2C2G 内存不够 | 加 3GB swap（原作者当年没加，被迫改架构） |
| 8 | 大陆节点 80 端口 | ICP 备案扫描 | 对外端口改 8080 |
| 9 | （本地）改完代码构建仍报旧错 | IDE 未保存的缓冲区覆盖了磁盘修改 | 改完 `Ctrl+K S` 全保存再构建 |

## 11. 想自己从头重练？两个方案

### 方案 A：在现有服务器上清空重来

**⚠️ 会丢失所有数据（用户账号、庭审记录、数据库）**，确认没有要保留的数据再执行：

```bash
cd /opt/DecisionCourt

# 1) 停容器 + 删数据卷（-v 是关键，不加则数据还在）
docker compose down -v

# 2) 删代码和配置
cd /
sudo rm -rf /opt/DecisionCourt

# 3) 从 §4.5 建目录开始重做
sudo mkdir -p /opt/DecisionCourt
sudo chown -R ubuntu:ubuntu /opt/DecisionCourt
```

然后从 §5 传代码开始，一步步做。

> 想更彻底（连 Docker 都重装）：
> ```bash
> sudo apt-get purge -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
> sudo rm -rf /var/lib/docker /etc/docker
> ```

### 方案 B：开一台新服务器重做（更推荐）

好处：现有的演示环境保持可用，新机器上完整走一遍从零流程。流程完全一样，只是：

- 新 IP → §1 信息清单和 §6 的 `.env` 换 IP
- 安全组 → 新实例要单独配（放行 22 和 8080）
- 试试**香港节点** → 免备案，可以直接用 80/443，为第 3 阶段（域名 + HTTPS）做准备

## 12. 第 3 / 4 阶段会用到的东西

| 阶段 | 目标 | 关键动作 |
|---|---|---|
| 第 3 阶段 | 域名 + HTTPS | DNS A 记录 → `.env` 填 `DOMAIN=你的域名` → Caddy 自动签 Let's Encrypt 证书。**大陆节点绑域名必须 ICP 备案**（2-4 周），所以实际项目多用香港节点 |
| 第 4 阶段 | CI/CD 自动化 | 改 `.github/workflows/deploy.yml` 的镜像仓库地址 → 配 GitHub Secrets（`ECS_HOST` / `ECS_USER` / `ECS_SSH_KEY`）→ 之后 `git tag v1.0.1 && git push --tags` 全自动部署 |

第 4 阶段的 SSH 密钥用的就是 §3 生成的那一对——这也是为什么 §3 必须做。
