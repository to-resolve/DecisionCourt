## 🐛 实施过程中的 bug / 教训

### D.1: 跨包测试访问 agent private 函数需要 export helper

**问题**: courtroom 包 ecs_regression_v102_test.go 想调 `applySpeakerRebuttalCheck` (agent 包 private), 标准做法是加 export bridge 函数 (e.g. `ApplySpeakerRebuttalCheckForTest`) 或把测试移到 agent 包。

**教训**:
- 跨包测试首选方案: 把测试放在算法实现的包内 (本项目惯例)
- 次选方案: export `*ForTest` helper (但增加 API surface)
- 本 PR 采用次选: 把 `TestEcsRegression_RebuttalPrompt_Documented` 改为检查 model.RebuttalStatus 常量 (跨包可直接访问), 不直接验 baseRules 文本

### D.2: ESM `.ts` 扩展强制 (`lib/rebuttal.test.ts` import)

**问题**: Node `--experimental-strip-types --test` 在 ESM 模式下, `from "./rebuttal"` 找不到模块, 必须 `from "./rebuttal.ts"`。

**教训**: frontend 测试统一 `.ts` 后缀 (已存在惯例, transport.test.ts 也是这样), 写新测试时直接用。

### D.3: Evidence UUID vs display_id 前端映射

**问题**: 后端 `RebuttalLink.rebutted_evidence_id` 是 UUID (DB primary key), 但前端 `Evidence.evidence_id` 是 display_id (`E001`)。前端 chip 显示需要按 display_id 分组, 但 type 系统只暴露 `evidence_id`。

**教训**:
- PR-5 给 `Evidence` 接口加 `id` 字段 (UUID), 前端用 `id → evidence_id` Map 做 join
- Mock data 也需要补 `id` 字段 (PR-5 顺手补 3 处)
- 后续可优化: 后端 RebuttalLink JSON 直接带 `rebutted_evidence_display_id` 字段, 避免前端 join

### D.4: Windows TempDir 文件锁累积

**问题**: PR-4 又发现 1 个 (PR-3 已修 1 个, 总累计 3 个) `TestGateway_*_WrittenToLog` 测试在 Windows 上 TempDir cleanup 报 "file in use"。原因是 FileLogger 持有 file handle, t.TempDir() cleanup 时无法删除。

**教训**:
- 所有用 `FileLogger: true` 的测试都需要 `t.Cleanup(func() { gw.fileLogger.Close() })`
- 当前 v1.0.2 已修 3 个 (BudgetCompressThrottleAndLog / FallbackRetry / SmartCompressionInfo / AddUsageMultiDim), 后续若新增 FileLogger 测试必须同时加 t.Cleanup
