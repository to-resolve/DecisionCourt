## 🐛 实施过程中的 bug / 教训

### D.1: Node 24 JSX 测试限制

**问题**：`renderToStaticMarkup(React.createElement(...))` 测试 `.tsx` 组件时，Node 24.14 报 `ERR_UNKNOWN_FILE_EXTENSION .tsx`。即便 `--experimental-transform-types` 也无法直接处理 `.tsx`。

**教训**：
- 改用 `readFileSync` + `regex.match` 验证组件源码
- 真正的 React 行为靠 tsc + 浏览器人工验证
- 未来如需 jsx 测试，引入 `tsx` loader 或迁移到 vitest + jsdom

### D.2: Git Bash commit message 引号截断

**问题**：commit message 含反引号（`` `下一步` ``）时，Git Bash 把引号当 shell quote，导致 commit 失败。

**教训**：
- 用 `git commit -F <file>` 模式（写文件再从文件读）
- 避免 shell 转义陷阱

### D.3: SSR fallback 路径设计

**问题**：V2.0-PLAN.md §1.5 设计 `SilhouetteAvatar` 包装组件用 `mode` prop 控制 silhouette vs circle。

**简化**：改用 env var `NEXT_PUBLIC_USE_CIRCLE_AVATAR` 触发 fallback，理由：
- 用户改回旧头像最常见场景是"我不喜欢新版本想看回圆形" — 改 env var 重启即可
- `mode` prop 需改 AgentAvatar 调用代码（3 处），env var 是 0 改代码方案
- 未来 mode="lottie" 等升级仍可通过 mode prop 走（RoleSilhouette 已暴露 mode 类型）

**教训**：default + env var fallback 是 Next.js 项目通用模式（与 `NEXT_PUBLIC_USE_MOCK` 一致）

### D.4: CSS 颜色解耦的"解耦程度"

**问题**：第一版想用 Tailwind class（如 `bg-prosecution`）给 silhouette 头部 fill，但 SVG 内部 `fill="currentColor"` + 父 div className 控制颜色更灵活。

**教训**：
- SVG `fill="currentColor"` 是 CSS 颜色继承的标准做法
- 父元素 `class="silhouette-prosecutor"` 通过 `.silhouette-prosecutor { color: var(--silhouette-prosecutor); }` 控色
- 改色只需改 CSS var，不需改 SVG path
