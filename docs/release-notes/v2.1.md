## 🆕 新增功能（F1-F7 commit 汇总）

### F1: JudgeBiasMeter 冲击波位置修复（视觉 bug）

**根因**：v2.0 工作中 `JudgeBiasMeter.tsx:152` 把 shock 元素的 `left` 钉死在 `50%`（track 中央），不跟随 `targetPosition` 移动。指针 60% 时, 冲击波从 50% 喷出 — 视觉错位。

**修复**：
- `frontend/components/courtroom/JudgeBiasMeter.tsx`: `left: "50%"` → `left: \`${targetPosition}%\``
- `frontend/lib/animations/variants.test.ts`: 加 source-grep 测试（断言 `left: ${targetPosition}%` 存在 + 旧的 `left: "50%"` 删除 + globals.css 关键帧保留）

### F2: TrialReplay phaseBelief 按 phase 过滤（逻辑 bug）

**根因**：v2.0 工作中 `TrialReplay.tsx:188-193` 的 `phaseBelief` 直接返回 `beliefDiffs` 最后一条, 不区分 phase。opening / evidence / cross_exam / closing 几个 tab 都显示同一最终 belief — 误导用户以为法官在每个 phase 都重新评估。

**修复**：
- 三层 fallback 计算: 同 phase diff → 之前 rounds 兜底 → 全局兜底
- `frontend/components/trace/TrialReplay.test.ts` (NEW, 4 sub-test): source-grep 测试 phaseBelief 实现 + deps 含 reviewPhase + 5 色盘顺序 + 未发生 phase fallback

### F3: isJudging 死代码清理 + ADR 0035（重构 + 决策固化）

**根因**：`isJudging` prop 在 4 个组件接收, 但触发条件 `agent.agent_type === "judge" && isSpeaking` 依赖后端 `judge.speak` 事件, 而后端从未发过此事件（既成事实）。整个 `isJudging` 路径是死代码。

**修复**：
- `AgentAvatar.tsx` / `RoleSilhouette.tsx` / `DotAvatar.tsx` / `Silhouette.tsx` / `AvatarAnimations.tsx`: 删 `isJudging` prop + 删 `AvatarAnimationState.judging` 类型 + 删 `deriveAnimationState` 分支
- 保留资产: `judgeVariant` (lib/animations/variants.ts) + `.silhouette-gavel` / `.dot-judge-shock*` CSS class — v3.0 端侧 TTS 启用法官发言时可直接恢复
- **ADR 0035** (NEW): 「法官不发言」决策固化, 含 v3.0 启用 checklist（4 步恢复路径）

### F4: LLM_API_KEY 启动检测 + /health/llm + 前端 banner（静默启动修复）

**根因**：`main.go:61-64` 用 `log.Printf("warning: ...")` 而非 ERROR; `LLM_API_KEY` 未设时 server 启动正常, `/health` 返回 200, 但 courtroom 完全不可用; 用户建庭审后才在第一次 WS 事件失败时收到 toast — 典型静默死路。

**修复**：
- `backend/internal/llm/health.go` (NEW): `GetHealth()` + `maskKey()`（前 3 + *** + 后 4 掩码, 永不返回完整 key）
- `backend/internal/llm/health_test.go` (NEW, 4 sub-test): maskKey 5 case + 永不含完整 key 兜底测试 + 空 key / 非空 key 路径
- `backend/internal/api/handler.go`: 新增 `/api/v1/health/llm` 公开端点, 返回 `{"configured":bool,"provider":...,"model":...,"key_preview":"sk-***xxxx"}`
- `backend/cmd/server/main.go`: warn → ERROR + 染色 banner (红 + 黄)
- `backend/internal/search/provider.go`: `tavily` 用 `ErrProviderNotImplemented` sentinel, 让 main.go 检测后回退到 mock 而非 log.Fatalf
- `backend/internal/config/config.go`: `REDIS_URL` 字段加注释说明"当前 v1.x 不消费"
- `frontend/app/page.tsx`: 启动时 fetch `/health/llm`, `configured=false` 显示顶部 amber banner（不可关闭）

**关键纪律 (AGENTS.md §8 红线)**：
- ✅ 检测 key 是否非空（不读值）
- ✅ 返回 `key_preview="sk-***xxxx"`（永不返回全值）
- ❌ 不复制 key 到任何位置
- ❌ 不写 demo 脚本用真 key

### F5: 三个默认开关全部启用（性能 / 韧性加固）

**根因**：ADR 0013 (v0.9 LLM Gateway 工程化) 实现了 smart_compression / cache / breaker, 但 6+ 个月默认 false。本地开发模式要翻默认看实测效果。

**修复**：
- `backend/internal/config/config.go`:
  - `SmartCompression: envOrDefaultBool(..., true)` （was false）
  - `CacheEnabled: envOrDefaultBool(..., true)` （was false）
  - `BreakerEnabled: envOrDefaultBool(..., true)` （was false）
- `backend/internal/config/f5_default_test.go` (NEW, 2 sub-test): 默认值 = true + env=false 回滚路径
- `.env.example`: 加 5 个 env 注释（含 SmartCompression 5 行）
- `docs/observability/SWITCH-SOAK.md` (NEW): 翻默认后的可观测信号 / 冒烟流程 / 回滚手册

**回滚机制**（关键）：
- 设 `.env=false` 重启 backend 即生效，**无需重编译**
- 三个开关互相独立, 可单开单关
- 最坏情况损失: 1 分钟重启 + 一次环境变量编辑

### F7: DotAvatar 视觉优化 + 庭审中央案卷化（视觉升级）

**根因**：v2.0 silhouettes 路线（`RoleSilhouette` + 汉字剪影小人）经用户反馈"看不清楚谁是谁"，v2.1 改为**纯几何抽象 DotAvatar**：48px 色盘 + 角色汉字（控/辩/法/调/书）+ 状态装饰层。同时法庭中央加 `.scene-shell` 案卷化包装（装订线/折角/印章），修横向滚动 bug。

**新增组件**：

  - `speaking` → 金色 halo 呼吸

  - `judging` → 法官金印冲击波（保留为 v3.0 启用能力）
  - `confronting` → 双色外环挤压（仅控辩）
  - `listening/idle` → 静态

**修复**：
- `frontend/components/courtroom/AgentAvatar.tsx`: F3 清理 `isJudging` 后默认走 DotAvatar（保留 silhouette opt-in）
- `frontend/app/globals.css`: +354 行 CSS keyframes（dot-speak-halo / dot-orbit-rotate / dot-search-scan / dot-judge-shock 等）
- `frontend/components/courtroom/CourtroomScene.tsx`:

- `frontend/lib/animations/variants.ts`: listenVariant 从 y [0, 2, 0] 改为完全静止 (y=0); searchVariant rotate 缩到 ±8° (原 ±15°) + duration 1.5s→1.8s (v2.1 Bug-2 修)

**设计原则 (postmortem §5 规则 3「抽象 > 模拟」)**:

**测试**：
