**改动**: `Close()` 后将 `fl.file` 置 nil,允许下次 Write lazy reopen。

```go
// Close 关闭当前文件。下次 Write 会自动 lazy reopen 同一天的文件。
// (v1.0.1 修复: Close 后将 fl.file 置 nil,避免 Windows TempDir cleanup 时
// "file in use" 报错 — 测试场景下测试结束前必须 defer Close。)
func (fl *FileLogger) Close() error {
    fl.mu.Lock()
    defer fl.mu.Unlock()
    if fl.file != nil {
        err := fl.file.Close()
        fl.file = nil  // v1.0.1 新增
        return err
    }
    return nil
}
```

## 🐛 实施过程中的 bug / 教训

### D.1: v0.10.23/24 改动后测试期望值没同步

**问题**: v0.10.23 加 `applySpeakerNoveltyRetryLoop` (v0.10.23 commit `8dc80f7`),v0.10.24 加 `applySpeakerStanceJudge` (v0.10.24 commit `b601831`)。两者都在 speak 之后多调 2 次 LLM,但当时只更新 release notes,没同步 `react_runner_test.go` 的 8 个 `llm.Calls()` 期望值。

**教训**: 任何对 speak 之后加 retry 通路 / 调用 LLM 的逻辑改动,都必须:
1. 同步更新 `react_runner_test.go` 期望值
2. 在 commit message 里列"测试同步"行
3. 或**给 LLM 调用计数加一个包装函数**(e.g. `r.llm.CountCalls()`),让测试不直接依赖具体数字

### D.2: Windows TempDir cleanup 与 FileLogger handle

**问题**: `t.TempDir()` 在 test 结束时自动 `RemoveAll` 目录。如果 FileLogger 持有该目录下文件的 OS handle,Windows 会拒绝删除("file in use")。Linux/macOS 不报错,所以 ECS / GitHub Actions(ubuntu)上一直没暴露。

**教训**: 
- 在 Windows 上跑测试必须有 `t.Cleanup` 显式 Close 长生命周期的 file handle
- `FileLogger.Close()` 必须把内部 handle 置 nil,允许 lazy reopen
- 后续如果引入其他长持有句柄的资源(网络连接 / DB 连接),都要考虑 t.Cleanup

### D.3: captureLLMScripted.onCall 覆盖式 append

**问题**: 原代码 `capturedMessages = append([]llm.Message{}, msgs...)` 看似 append,实际每次**重新初始化空 slice 再 append**当前 msgs,因此只保留最后一次 call 的 msgs。在 v0.10.23/24 多次 LLM call 后,transcript 注入在第一次 call 的 system prompt 被覆盖丢失。

**教训**: 
- 多 call 场景必须用 `[][]T` (per-call slice of slice)
- 或加 `callIdx` 显式区分每次 call

### D.4: baseRules 第 16 条措辞需避开 test2 section 切分边界

**问题**: `TestProsecutorPrompt_ShouldHaveFindingSection_WhenFindingsExist` 用了 `indexAny([]string{"调查发现", "调查活动", "InvestigationFinding"})` + `strings.Index(rest, "\n## ")` 切片。如果 baseRules 里含"调查活动"且在 buildInvestigationContext 之前,baseRules 会被误判为"调查活动 section"。

**教训**: 写 prompt 时避免 section header 关键词出现在非 section 内容里,或加 `\n## section end\n` 终止 marker。
