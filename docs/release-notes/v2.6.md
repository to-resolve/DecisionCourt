## 🆕 新增功能（v2.6 commit 汇总）

### D2 (1/4): react_runner.go 三处 WARN 日志

`backend/internal/agent/react_runner.go::streamSpeakContent` 三个 silent 失败点加 `slog.Warn`：

- **ctx-cancel 分支** (line 982-)：`slog.Warn("react_runner streamSpeakContent ctx canceled", "chunks", chunks, "raw_prefix", truncateForLog(collected.String(), 200))`
- **chunk Err 分支** (line 992-)：`slog.Warn("react_runner streamSpeakContent chunk err", "err", c.Err, "chunks", chunks, "raw_prefix", truncateForLog(collected.String(), 200))`
- **empty lastExtracted 分支** (line 1053-)：替换原 inline truncation 为 `truncateForLog(collected.String(), 500)` helper

### D2 (2/4): truncateForLog helper

新增 `func truncateForLog(s string, n int) string`：

- 字节截断到 n 字节
- 末尾追加 `...(truncated, total=NB)` 注明总字节数，便于诊断完整长度
- 接受 UTF-8 末尾切半风险 vs 日志可读性权衡（仅用于 WARN 日志）

### D2 (3/4): saveAgentMessage 拦截 + REJECT 日志

`backend/internal/courtroom/service.go::saveAgentMessage`：

- 入口 `strings.TrimSpace(speaker.Content)==""` 拦截保留（v2.5 之前已加）
- 新增 `log.Printf("[v0.6][saveAgentMessage] REJECT empty content: session=%s agentType=%s phase=%s round=%d agentID=%s (silent LLM failure guard)", ...)`
- sentinel 关键词从 `silent error guard` 改为 `silent LLM failure guard`（便于日志检索 + 与 v0.10.17 历史修复一致）

### D2 (4/4): caller "log + skip" 契约

6 处 bare call 包成 `if err := ... { log.Printf("[v0.6][<scope>] skip ... broadcast due to empty content: %v", err) } else { broadcast }`：

- `resumeOpening` 2 sites（prosecutor + defender）
- `resumeClosing` 2 sites（prosecutor + defender）
- `finishTrial` 2 sites（closing prosecutor + closing defender）

**不**改 `RunOpeningSpeeches` / `runCrossExamRound` 的 hard-fail 行为（D2 修复只针对恢复路径，正常 trial 路径硬 fail 是合理的）。

### D3 (1/3): transitionPhase 保留 round

`backend/internal/courtroom/service.go::finishTrial` 第 1521 行：

- 原：`transitionPhase(&session, model.PhaseClosing, 0)` —— 把 round 字段重置为 0
- 改：`transitionPhase(&session, model.PhaseClosing, session.CurrentRound)` —— 保留 round 字段

### D3 (2/3): maxRound helper

新增 `func maxRound(messages []model.Message) int`：

- 处理 nil / 全 0 / 混合边界（5 个 sub-test 覆盖）
- 用于 `finishTrial` fallback `trial_summary` 文案，反映跨 phase（opening + cross-exam + closing）真实轮数

### D3 (3/3): trial_summary 文案

`service.go::finishTrial` fallback 文案第 1625 行：

- 原：`fmt.Sprintf("本场庭审共 %d 轮。...", session.CurrentRound)` —— 已被前一行 zero，永远 0
- 改：`fmt.Sprintf("本场庭审共 %d 轮。...", maxRound(messages))` —— 真实轮数

## 📝 反思

### 触及 §2.1 裁决逻辑：**轻**

v2.6 D3 改动是 `finishTrial` fallback 文案 + `transitionPhase(round)` 参数；**不**改 `JudgeFinalDecision` / `GenerateVerdict` / direct verdict 选择算法。D2 不改裁决逻辑。

按 AGENTS.md §2 规则，触及裁决逻辑的"轻"变化属于"用户拍板即可实装"范畴（vs 中度需讨论 4 判定标准，强需先讨论后做）。本次用户授权"项目干净一些"+ 我 ExitPlanMode 出 6 PR 计划 + 用户授权"开始吧" — 完整走 §2 规则。

### v2.6 教训

1. **孤儿分支是技术债**：`fix/cross-exam-content-empty` 分支基于旧 base `29daff0`（v1.0.0 前）与 main 平行，merge 冲突爆炸。备份价值 = 1（commit hash 在 origin 永久保留），但长期"忘了这是什么"的用户认知成本高。教训：fix 分支开工后**尽量**当天合 main 或 rebase 到 main，超过 1 周 = 重新评估。
2. **同源 D2 + D3 一并修**：D3 是 D2 的次生（D2 让 messages content 全空 → GenerateVerdict 看到空 messages → fallback → fallback 又显示 0 轮）。两个 bug 同源（`react_runner` 流式失败 + `finishTrial` 状态字段），分两次 PR 会让 review 反复对照上下文。本次**单 commit** 同时修 D2 + D3，让 ADR 0040 / release notes 一次讲清。
3. **sentinel 关键词稳定性 = 可观测性基础设施**：D2 拦截 error 含 `silent LLM failure guard` 关键词，配合日志 grep 让未来 silent error 黑洞可观测。教训：sentinel 关键词必须有 regression test（`TestD2_ErrorMessage_ContainsSentinel`）守护，防止未来重构误改。
4. **不修根因也能收尾**：D2 修复**不**重构 `streamSpeakContent` 流式解析逻辑（commit message 列为后续项），仅加 silent error 检测 + 拦截。fallback 行为正确（不让空 content 污染 DB），根因留待下次 PR。教训：silent error 黑洞**先**让黑洞可见，再**修**根因，**不**同时做两件事。
