### D.2 教训: "看似未做" 实际 "已做但配置不一致"

PR-A 任务标题"启用 FileLogger"给人感觉是从 0 开始, 实际 FileLogger 代码 + docker + .env 全部已就位, 唯一不一致是 `config.go` 默认 false。这意味着:
- **生产 compose 部署** ✓ 工作 (compose 覆盖)
- **本地 dev (不跑 compose)** ✗ 静默 (拿 default false)
- **CI 测试** ✗ 静默 (同上)

教训: **"X 没启用" 不一定是"代码缺", 也可能是"配置不一致"**。修配置默认值比补代码更高效。

### D.3 教训: 文档 vs 实现错位累积

3 处文档错位反映 "写注释的人没看实现":
- `.jsonl` vs `.log` — 注释抄自早期规划文件, 实现后没人回头修
- "35 字段" vs "38 字段" — LogEntry 字段数 5 个月里加了 3 个 (compression + budget v2 + sliding tokens)
- `./logs:/app/logs` vs `./logs/backend:/app/logs` — 早期 compose 计划, 实现后路径加了一层 backend/

教训: **每加 LogEntry 字段时, 应同时更新 .env.example 注释**。可考虑加 lint 验证 (e.g. struct field count 注释)。

### D.4 教训: 测试命名 vs 任务描述

任务要求 `TestFileLogger_BasicWrite` + `TestFileLogger_DirectoryCreate`, 实际有 `TestFileLogger_WritesJSON` + `TestFileLogger_AppendsMultiple` + `TestFileLogger_DateRotation`。两者覆盖有重叠但不重复:
- `BasicWrite` 显式校验 timestamp 契约 (WritesJSON 没显式验)
- `DirectoryCreate` 显式验 3 层缺失 (其他 3 个都用 t.TempDir())

教训: **测试命名按"用户视角" (BasicWrite / DirectoryCreate) 比"实现视角" (WritesJSON) 更易对接**。本次不重命名已有测试 (避免 git blame 破坏), 而是补 2 个新测试覆盖缺口 + 强化契约。
