## 🆕 新增功能（v2.3 commit 汇总）

### P0-1: observability 注入骨架（nil-safe）

**7 文件构造器加 `observability.Metrics` 参数**：

- `agent_gateway.NewWithConfig` 末尾加 `metrics observability.Metrics`
- `NewResponseCache(ttl, max, metrics)` / `NewLLMBreaker(cfg, fallback, metrics)` / `NewPromptCompressor(cfg, metrics)` / `NewThrottler(metrics)` / `NewRetryer(metrics)` / `NewRetryerWithBackoff(d, metrics)` / `NewTokenBudgetWithStore(store, metrics)`

**关键设计**：`metrics=nil` 时所有埋点 no-op，单测与离线脚本**不**被强制要求构造 metrics 实例（向后兼容）。

**装配**：`cmd/server/main.go` 把已有的 `metrics` 实例传入 `agent_gateway.NewWithConfig`。

### P0-2: gateway.go 核心埋点

- cache hit 路径：`llm_call_total{cache=hit}` + tokens counter (`input_cached` / `output_cached`)
- cache miss 路径：`llm_call_total{cache=miss}` (发起) + `llm_call_duration_seconds{status}` + tokens counter (`input` / `output`)
- budget exhausted 拒绝：`budget_rejected_total{model, agent}`
- StreamComplete 入口：`llm_call_total{stream=true}`；出口：`llm_call_duration_seconds{stream}` + tokens (`output_stream_estimated`)

### P0-3: cache.go 5 个埋点

- Get hit/miss（过期也走 miss 路径）
- Put insert/update 分开（labels 区分）
- LRU evict + EvictSession 分开（labels 区分）
- size gauge 仅在 size 变化时 SetGauge（避免高频原子写热点）

### P0-4: breaker.go 3 个埋点

- `OnStateChange` 任何 from→to 转换都埋 `llm_breaker_state_change_total{from,to}`
- gauge `llm_breaker_state` 同步当前状态（0=closed / 1=half-open / 2=open）
- `triggerFallback` 区分 `open` / `half-open-throttled` 两个 reason

### P0-5: prompt_compressor.go 4 个埋点

- 跳过路径：`compression_applied_total{status=skipped_normal}`
- 应用路径：`compression_applied_total{strategy=scored|legacy, trigger}`
- `prompt_compression_ratio` + `prompt_compression_duration_seconds` 两个 histogram
- `prompt_compression_summary_inserted_total` 兜底摘要

### P0-6: throttler / token_budget / retryer 3 文件埋点

- throttler：`llm_throttle_applied_total{task_type}` / `llm_throttle_exempted_total{task_type}`
- token_budget：`budget_warning_total{level=compress|throttle|exhausted}`（即使无 OnWarningFunc 注册也埋，dashboard 可见）
- retryer：`llm_retry_attempt_total`

### P0-7: metrics_test.go 9 个新 sub-test

- `TestMetrics_CacheHitMissPutEvictSize` — cache 5 个埋点全验证
- `TestMetrics_CacheEvictSession` — EvictSession 单独
- `TestMetrics_BreakerStateChangeAndFallback` — breaker 3 个埋点
- `TestMetrics_PromptCompression` — compressor skipped + 应用
- `TestMetrics_ThrottlerAppliedExempted` — 触发 + 豁免
- `TestMetrics_Retryer` — 重试计数
- `TestMetrics_GatewayEndToEnd` — cache miss → cache hit 完整路径
- `TestMetrics_GatewayBudgetExhausted` — budget 拒绝路径
- `TestMetrics_TokenBudgetWarning` — warning 升级埋点
- `TestMetrics_NilSafe` — nil metrics 全路径不 panic

## 📝 反思

### 触及 §2.1 裁决逻辑：**0**

v2.3 全部改动都是 observability 埋点 + 文档同步，不动审判逻辑、不动 §2.1 任何路径。

### v2.3 教训

1. **metrics 注入要 nil-safe** —— 单测和离线脚本不应被强制要求构造 fake metrics，否则会污染所有老测试（v2.3 §3.1 ADR 0037）
2. **gauge 写是原子竞争热点** —— cache size 这种高频变化必须只在"变化时"SetGauge，否则 Get 快路径退化为慢路径（v2.3 §3.2 ADR 0037）
3. **业务事件 vs OnWarningFunc 注册无关** —— budget warning 是 ops dashboard 信号，不应依赖业务侧是否注册 handler（v2.3 §3.3 ADR 0037）
4. **构造器改签名要 break 一致** —— 7 文件构造器加 metrics 参数后，所有 `_test.go` 文件必须同步更新；批量 sed + python + 手工配合是最快的（v2.3 实施实录）

### AGENTS.md §11 实践验证

v2.3 触发 SWITCH-SOAK.md §2 表格更新（虽然 §11 业务测试是 v2.2 提出的，本轮 §11 仍是"业务指标必须可观测"的延伸）。
