## 🐛 实施过程中的 bug / 教训

### D.1: ECS 沉淀的 P1-2 "说谎 24 天" 是 **v1.0.0 必修**
- main.go:223 硬编码 `v0.9.2`,实际跑 v0.10.20,v0.10.21 PR-B 修复
- **教训**:启动日志的 version 字段必须有可信 source(ldflags + git describe),任何硬编码都可能在迭代中撒谎

### D.2: DeepSeek API 文档变更必须主动跟进
- 用户提示前,Agent 不会主动查 DeepSeek API
- v1.0.0 若不迁移会带死默认值发布,首次部署 trial 就 404
- **教训**:外部 API 依赖必须有"配置迁移 checklist",文档变更要定期 review

### D.3: model name 字面量散落测试文件
- 8 个 agent_gateway 测试硬编码 `deepseek-chat`,本次迁移要 sed 全量替换
- **教训**:后续 Phase B 计划,把 mock 测试 model name 集中到 `internal/agent_gateway/test_constants.go`

### D.4: 本地无 DeepSeek API key 无法实测 v4
- `curl /models` 鉴权拒绝,`POST /chat/completions` 无 key 也拒绝
- **教训**:决策依据 = 官方文档 + ADR 文档化风险,接受"实施后用户首次跑可能 404"的概率(已在 ADR 0029 §3 标注)

### D.5: `ClassifyError(context.Canceled)` 不映射到 OPENING_SPEECHES_FAILED
- 修复前 P3-2 测试想验证 `context.Canceled` → OPENING_SPEECHES_FAILED,实际 ClassifyError 只对 `agent.ErrReactMaxIterations` 路由
- **教训**:测试场景要用真实生产信号(ReAct max iterations),不是中间错误(context canceled),否则会推动"无意义"的代码扩展
