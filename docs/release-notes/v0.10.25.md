## 🐛 实施过程中的 bug / 教训

### D.1 ToastAction type 字段错位 (action vs onClick)

**症状**: 第一版 `toastFatal` 传 `actions: [{label, action, style}]`, 编译失败 — `ToastAction` 是 `{type, label, onClick?}` 而非 `{action}`。

**根因**: 没看 toastStore.ts 类型定义, 凭"ToastAction 应该有 action 字段"假设写。

**修复**: 改为 `actions: [{type: "investigator_retry", label: "继续庭审 (重试)", onClick: () => globalWsRef()?.send({action: "continue_cross_exam"})}]`。

**学习**: **写新代码前先读 type 定义** (3 分钟 grep 比 30 分钟编译错误排查快)。

### D.2 UserActionRequest.action 联合类型限制

**症状**: 第二版 retry 调 `restart_opening`, TS 编译失败 — "restart_opening" 不在联合类型。

**根因**: UserActionRequest.action 联合类型只包含 `submit_evidence | direct_verdict | skip_agent | answer_question | pause | resume | interrupt | start_cross_exam | continue_cross_exam | reopen_trial`。"restart_opening" 是 error UFE 的 recovery 字段, 不是 user_action。

**修复**: 改用 `continue_cross_exam` (后端进入下一轮, lawyer 重新调 investigator_search tool)。

**学习**: **retry 不一定要"重做同一件事"**, 推进流程也能达到重做 investigator 的效果 (比 reopen_trial 轻量)。

### D.3 wsRef 跨组件访问难题

**症状**: React useRef 局限 — store (非 React 上下文) 拿不到 CourtroomScene 的 wsRef。

**根因**: React 16+ useRef 是组件级, 跨组件不共享。

**解决**: 提取 module-level `wsHolder.ts`, CourtroomScene 在 setWs 时调 `setGlobalWsRef(socket)`, store 在 retry onClick 调 `globalWsRef()?.send(...)`。

**学习**: **Module-level singleton 是 React 跨上下文共享的最小开销方案**, 优于 Context API (避免重渲染)。

### D.4 memory hydrate 设计取舍

**取舍**: localStorage (跨刷新) vs sessionStorage (单 session)
- 选 localStorage: 跨刷新仍可用, 与 auth.ts token 模式一致, 用户重新打开庭审页能立刻看到上次的 memory
- 代价: 多 tab 同时打开会共享缓存, 但项目庭审页是单 tab 设计, 风险低

**学习**: **缓存策略与产品使用模式对齐**, 不是越严格越好。

### D.5 不加 schema FK 约束的判断

**取舍**: 加 ALTER TABLE FK 约束 (1 天工作量膨胀) vs 仅主动验证 + DecisionEvent audit (0.5 天)
- 选主动验证: 当前 schema 没有硬 FK 约束 (GORM 不会自动加), 加约束是预防性
- 主动验证已经捕获"session_uuid 是零 UUID / 不存在 / 非法"等所有孤儿行场景
- DecisionEvent audit 提供未来查询能力, 不破坏 schema 兼容性

**学习**: **silent error 修复的最小可行方案**, 不要为了"完美"做超出需求的工作量。
