## 3. 根因分析（5 Whys）

### Why 1：为什么 3D 庭审场景做不好？
- ZCode Agent 没有 GLTF/FBX 模型资产
- ZCode Agent 没有 PBR 材质贴图（normal/roughness/ORM）
- ZCode Agent 没有 HDRI 环境贴图
- ZCode Agent 没有 Substance/Blender 工具
- ZCode Agent 没有 3D 美术/灯光摄影经验

### Why 2：为什么 Agent 没有这些能力？
- LLM 训练数据不包含"好的 3D 场景"参考（仅有通用代码模式）
- Agent 不能 Web 搜索（环境网络限制 Google/DDG/Wiki 不可达）
- Agent 不能 AI 出图（无工具）
- Agent 不能调用设计师（无人介入）

### Why 3：为什么没有早一点承认失败？
- 每次用户反馈"丑"，Agent 试图"再调一下"（深木 → 浅橡木 → 游戏风格）
- 9 个 PR-D2 commit 累计 500+ 行 diff 都被推翻
- 反复试错延迟了"放弃"的判断

### Why 4：为什么反复试错？
- 缺乏"能力边界"的元认知
- 把"用户反馈"当作"参数调整"（调一下颜色 / 改一下布局 / 调一下灯光）
- 没有在第一次失败时就承认"3D 是 Agent 能力上限"

### Why 5（根因）：为什么缺乏元认知？
- ZCode Agent 设计目标包含"不撞南墙不回"
- 但 LLM 默认行为是"在用户反馈下持续优化"——而不是"承认无法做到"
- 缺少**自我能力评估**机制
- 缺少"如果 3 次失败就换方向"的硬规则

## 5. 教训（Lessons Learned）

### 5.1 给 ZCode Agent 自己

1. **"如果 3 次失败就承认能力边界"**——本项目 PR-D2.0 → PR-D2.5 已经是 5 次失败，应该早就 stop
2. **不要把"用户反馈"当"参数调整"**——用户说"丑"是定性判断，不是"再调一下"
3. **能力评估先于方案选择**——3D 需要资产能力（模型/贴图/HDR/工具）+ 审美判断 + 工具使用，缺一不可
4. **抽象 > 模拟**——法庭的"语义"（天平 / 金色 / 对比）能用 CSS 表达，不需要 3D 物理真实
5. **不要在没资源时硬撑**——保留能力范围内的最佳结果

### 5.2 给项目（决策者 / 未来维护者）

1. **v2.0 REDESIGN 失败不是方案问题**——是 Agent 能力边界问题
2. **圆点剪影已足够**——v1.0.4 PR-C3 实现的 framer-motion 6 状态动画（speak/think/listen/search/judge/confront）功能完整
3. **未来类似"重做"需求**——应该先评估"Agent 能否做到"，再决定是否重做
4. **视觉重做的正确路径**——用户**提供参考图**，Agent **照着做**，不"自由发挥"

### 5.3 给 AGENTS.md 工作流

**新规则（建议加入 AGENTS.md §2 决策规范）**：
- Agent 能力边界**前置评估**——超出能力的任务，**不开始**
- 任何"视觉重做"任务**先确认资源**——资产 / 工具 / 参考图
- 失败 ≥ 3 次 → **主动报告**"需要换方向"——不"再调一下"
