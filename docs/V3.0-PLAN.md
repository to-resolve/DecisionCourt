# v3.0 规划文档 — 端侧 TTS（庭审语音化）

> **状态**: ⏸ **占位 + 调研阶段，待 v2.0 完成后启动**
> **创建日期**: 2026-08-21
> **优先级**: P2（v2.0 后）
> **目标 release**: v3.0 在 v2.0 基础上 3-4 周 / 2-3 PR（视调研结果调整）
> **触及 §2.1 裁决逻辑**: **轻**（语音朗读不改变裁决结果，但需考虑可访问性 + 用户偏好）
> **核心定义**: "端侧 TTS" = 完全离线 TTS（不依赖云端 TTS 服务），模型在本地运行

## 0. 上下文与决策

### 0.1 触发
用户 2026-08-21 反馈："想的是 2.0 完善人物动态等之前订的那些，3.0 研究端侧 tts 等"。

### 0.2 决策记录
- **v2.0 = 剪影小人升级版**（原 V1.0.5 升格，详见 [V2.0-PLAN.md](./V2.0-PLAN.md)）
- **v3.0 = 端侧 TTS（离线）** — 用户明确选"端侧"而非"云端 TTS"

### 0.3 端侧 vs 云端
- **端侧（用户选）**: 模型本地运行，零云端依赖，隐私保护好，离线可用
- **云端**: 用 Azure TTS / ElevenLabs / OpenAI TTS，质量高但需 API key + 网络
- **用户优先选端侧**: 个人项目 + 隐私 + 离线可用

### 0.4 触及 §2.1 裁决逻辑：轻
- TTS 是"朗读"层，不改变裁决算法
- 但需注意：TTS 失败时不能阻塞庭审（fallback 到纯文字）
- 法官/律师/调查员/书记员不同角色 TTS 音色差异化（与 v2.0 角色对应）

## 1. 业务痛点（为什么需要 TTS）

### 1.1 现状
- 庭审过程纯文字：用户必须盯着屏幕读
- 多模态庭审缺失：v0.6 信念引擎 / v1.0.2 反驳链 都是文字呈现
- v2.0 剪影小人升级后，**角色会动但没声音**——视觉与听觉割裂

### 1.2 目标（v3.0 落地后）
- **离线可用**：无网络环境下仍能朗读（个人项目最关键需求）
- **多角色音色**：5 个 agent（控方/辩方/法官/调查员/书记员）各有特色
- **可控制开关**：用户随时可关闭 TTS（accessibility 选项）
- **不增加云端依赖**：纯前端 + WASM / Web Worker

## 2. 设计方案（待调研）

### 2.1 候选 TTS 引擎

| 引擎 | 模型大小 | 浏览器支持 | 中文质量 | 集成难度 | 备注 |
|---|---|---|---|---|---|
| **Piper TTS** | 15-60 MB / 音色 | WASM (piper-wasm) | ⭐⭐⭐⭐ (中文 ONNX 模型) | 中 | Mozilla 项目，离线推理快 |
| **Coqui TTS** | 50-200 MB | WASM (coqui-sttts) | ⭐⭐⭐ (XTTS-v2 多语言) | 中高 | Coqui 工作室，已停止维护但代码可用 |
| **Kokoro TTS** | 80 MB | 浏览器原生 fetch + ONNX Runtime Web | ⭐⭐⭐⭐⭐ (中文) | 中 | 最新开源，音质好 |
| **Edge TTS** (云端) | 0 MB | Web Speech API | ⭐⭐⭐⭐⭐ | 低 | **不符合端侧要求**，仅备选 |
| **Web Speech API** (浏览器原生) | 0 MB | 浏览器内置 | ⭐⭐⭐ (依赖浏览器/OS) | 低 | **不算真正端侧**，OS 提供语音 |

**优先级**：先调研 Piper / Kokoro（轻量 + 中文质量 + 活跃维护）

### 2.3 引擎抽象接口

```typescript
// frontend/lib/tts/engine.ts

export interface TTSEngine {
  load(): Promise<void>;                      // 加载模型 (~60MB, 进度条)
  speak(text: string, voice: VoiceId, opts?: SpeakOptions): Promise<void>;
  stop(): void;
  isReady(): boolean;
  voices(): VoiceId[];                         // 5 个 agent 音色
}

export interface SpeakOptions {
  rate?: number;       // 0.5-2.0, 默认 1.0
  pitch?: number;      // -1.0-1.0, 默认 0
  onStart?: () => void;
  onEnd?: () => void;
  onError?: (err: Error) => void;
}
```

## 7. 风险与缓解（待调研后细化）

| 风险 | 影响 | 缓解 |
|---|---|---|
| 中文 TTS 模型质量差 | 庭审朗读体验差 | 调研期严格筛选 + 用户试听决定 |
| 模型首次加载时间长 | 庭审启动延迟 | Service Worker 缓存 + 延迟加载（庭审页打开后才加载）|
| 模型大小超限（CDN 静态资源 100MB 限制） | 模型加载失败 | 切片下载 + IndexedDB 缓存 |
| WASM 性能差（旧 CPU） | 朗读卡顿 | 引擎选择时考虑旧 CPU fallback |
| 模型许可证不允许商用 | 法律风险 | 调研期审查（§5.3）|
| 用户关闭 TTS 后忘记开启 | 体验问题 | 默认开启 + 设置项持久化到 localStorage |
| TTS 朗读与发言文本不一致（错字） | 信任问题 | 显示原始文字 + TTS 文本（如有差异）|

## 9. 不做什么（明确边界）

- ❌ **不引入云端 TTS**（用户明确选端侧，隐私 + 离线）
- ❌ **不做语音克隆**（用户没要求，且涉及训练数据 + 法律风险）
- ❌ **不做 STT 语音输入**（v3.0 仅 TTS 输出，STT 是 v3.x 后续）
- ❌ **不做庭审录音回放**（v3.0 仅 TTS 朗读发言，不录制）
- ❌ **不做多语言**（v3.0 仅中文，英文 / 其他语言是 v3.x 后续）
- ❌ **不绑死单一 TTS 引擎**（抽象接口 + 引擎可替换：Piper 失败可换 Kokoro）
